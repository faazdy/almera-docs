01

Jerarquía y acceso

El módulo opera bajo una jerarquía de cuatro niveles que debe respetarse para que reportes y seguimiento funcionen correctamente.

1. Tipo de Proyecto Define las "reglas de juego": campos, flujo, codificación, qué pestañas de actividad se habilitan.
2. Proyecto La iniciativa específica, asociada a un tipo, con nombre y fechas globales.
3. Cronogramas Fases o etapas del proyecto, cada una con su propio peso porcentual.
4. Actividades Tareas puntuales dentro de un cronograma, con responsable, fechas y (si se habilita) presupuesto, recursos e indicadores.
Ruta Admin → Proyectos

La pantalla se divide en dos: la sección derecha configura el Tipo de Proyecto; la sección izquierda gestiona los Proyectos específicos.

Si un usuario ve "Proyectos" pero no ve la pestaña "Tipos de Proyecto", es un tema de privilegios — no un error del sistema. Ver sección 4.
Regla obligatoria: todo proyecto debe estar asociado a un Tipo de Proyecto. El orden siempre es: crear el Tipo → crear el Proyecto → crear Cronogramas → crear Actividades.
02

Configurar el Tipo de Proyecto

Antes de crear cualquier proyecto de un tipo nuevo, hay que definir su estructura y comportamiento.

Ruta Admin → Proyectos → pantalla derecha → Adicionar tipo
1

Clic en Adicionar tipo y registre el nombre del tipo de proyecto.

2
Parámetros generales

Todos vienen desactivados por defecto — márquelos si aplican.

Indicadores asociados Múltiples años Asociar a procesos Marco estratégico
3
Codificación

Patrón con %Y (año) y %C (consecutivo). Defina el padding (dígitos) y si el consecutivo es anual (se reinicia) o único.

Ejemplo
Patrón%Y-%C
Padding5
Resultado2026-00001
No sobreparametrice. Habilite solo lo que realmente se va a usar — activar opciones de más deja pestañas vacías en el proyecto y confunde al usuario final.
Campos adicionales (Atributos)

Ruta: Tipo de Proyecto → Configuración → Atributos → Nuevo campo adicional. Defina tipo de dato, código, y marque Requerido si aplica. El campo aparecerá en la información general del proyecto tras grabar y refrescar.

03

Flujo de trabajo — Estados y transiciones

No todos los tipos de proyecto necesitan flujo — depende de si se requiere trazabilidad o revisión por otro usuario en distintas etapas.

Ruta Tipos de Proyecto → Configuración → Estados / Transiciones
1

Cree los estados (fases) por los que pasará el proyecto — ejemplo real: Registrado → Seguimiento → Cumplimiento → Cerrado.

2

Marque "Tiene resumen" en el estado que corresponda — habilita el resumen de avance (sección 9).

3

Cree las transiciones (de qué estado sale, a cuál llega) y, si aplica, el enrutamiento a un usuario específico con el ícono verde Agregar.

"Tiene seguimientos" es por estado, no global. Si el botón "Adicionar seguimiento" no aparece en un estado del proyecto, hay que entrar a ese estado específico en la configuración y activar la casilla — se repite para cada estado donde se quiera permitir.
No existe una pestaña fija de "segunda/tercera línea" como en Planes de Mejora. Para lograr ese control, se crea un flujo con más estados (ej. Seguimiento → Cumplimiento, validado por otra área).
04

Privilegios

Existen dos niveles de privilegios, independientes entre sí.

Sobre el Tipo de Proyecto Se recomienda limitado. Ruta: Tipos de Proyecto → Privilegios → Administrar privilegios → buscar usuario → definir consulta / administrador / editar / registrar.
Sobre un Proyecto específico Cada proyecto tiene su propia pestaña Privilegios. Buscar usuario, definir administrador / consulta / adicionar seguimientos, y clic en el ícono verde Adicionar.
05

Crear el proyecto, cronogramas y actividades

Ruta Admin → Proyectos → pantalla izquierda → Adicionar
1
Crear el proyecto

Elija el Tipo de Proyecto, defina el consecutivo, asocie un proceso si aplica, registre nombre y fechas del proyecto. Grabe.

2
Adicionar cronograma

Código, nombre, responsable y peso (importancia porcentual sobre el total del proyecto), fecha de inicio y fin. Un proyecto puede tener n cronogramas.

3
Adicionar actividad (manual)

Ítem, nombre, descripción, fecha inicio/fin (o una sola fecha si es Hito), y usuario responsable. Clic en Adicionar.

4
Carga masiva (Excel)

Descargue la plantilla del sistema, complete siguiendo la misma estructura (responsable = login del usuario, fechas en formato fecha) y vuelva a cargar el archivo.

5
Campos adicionales de actividad

Ruta: Configuración → Actividades → Nuevo campo adicional. Primero cree un Grupo — el campo debe quedar asociado a él antes de poder crearlo.

06

Gestión presupuestal

Dos maneras de controlar costos, según el nivel de detalle necesario.

A nivel de Actividad Pestaña Costos de la actividad: registre el presupuesto planeado. Al reportar el seguimiento de la actividad, registre también el valor ejecutado — el sistema suma automáticamente a nivel de cronograma y proyecto.
A nivel de Atributos Cree dos campos manuales en el Tipo de Proyecto (Atributos): "Presupuesto aprobado" y "Presupuesto ejecutado". Se diligencian a mano, sin suma automática.
Si usa la opción de Atributos (manual), inactive la opción de presupuesto a nivel de actividad para ese tipo de proyecto, para no dejar dos lugares distintos donde registrar presupuesto.
07

Seguimiento y cierre de actividades

El proyecto se ve en dos visuales: Edición (planear) y Seguimiento (ejecutar, ver avance ponderado).

1

Entre a la actividad. Verá Iniciar actividad si tiene fecha inicio y fin, o directamente Terminar actividad si es Hito (una sola fecha).

2

Registre fecha y porcentaje de avance — es acumulativo, se va sumando hasta llegar al 100%. Adjunte evidencias si aplica. Grabe.

3

Al 100%, la actividad se marca finalizada y desaparece del Plan Individual del responsable (puede requerir refrescar la pantalla).

No hay notificación automática por correo al asignar el responsable de una actividad nueva — siempre debe enviarse manualmente.
Seguimientos generales del proyecto

Ruta: visual de Seguimiento → Información general → Adicionar seguimiento (registrar fecha, descripción, evidencias). Se pueden crear estados propios para los seguimientos en Configuración → Seguimiento (ej. "Etapa de revisión", "Cumplimiento") para etiquetar a qué etapa corresponde cada registro.

08

Indicadores asociados a actividades

Ruta: dentro de la actividad → pestaña Indicadores. Busque uno existente o cree uno nuevo (requiere ficha técnica completa).

El indicador no se mide desde Proyectos. Vincularlo solo relaciona el indicador con el proyecto — la medición real (variables frente a meta) se hace exclusivamente en el Módulo de Indicadores. El porcentaje que se ve en Proyectos es el cumplimiento de actividades, no del indicador.
09

Resumen y visualización de resultados

Parámetro obligatorio: "Mostrar resumen de cronogramas" (Configuración general) debe estar activo para que se muestre el resumen gráfico de avance.

Con el parámetro activo, la pestaña Información general / Resumen muestra:

% avance total del proyecto Avance y peso por cronograma Ejecución real vs. esperada Filtros por rango de fecha Descarga del gráfico Zoom a actividades atrasadas
10

Organizar tipos de proyecto y reglas del sistema

Si varios tipos de proyecto en realidad pertenecen a la misma iniciativa (por cambios de nombre a lo largo de los años), márquelos como "Depende de" un tipo macro, dentro del Tipo de Proyecto.

Error común: crear un Tipo de Proyecto distinto por cada variante, en vez de un solo tipo con un campo de categoría para clasificar. Crear tipos separados implica varias plantillas distintas y dificulta consolidar la información.
Reglas que no se pueden resolver sin soporte
Eliminar un Tipo o Proyecto No se puede si ya tiene cualquier registro asociado, así se haya eliminado luego. Debe solicitarse a Soporte Almera (lo hacen en base de datos).
Cambiar el "Tipo" de un proyecto Bloqueado si el tipo de destino no tiene exactamente los mismos campos que el de origen. Garantice la misma parametrización y solicite el movimiento a Soporte Almera.
Si un proyecto no aparece en el listado, revise el filtro superior de Vigencia — selecciónelo en "Todas" y haga clic en Filtrar.
11

Integración con Plan Estratégico (Cuadros de Mando)

La vinculación NO se hace desde Proyectos. Se hace al revés: desde un Cuadro de Mando ya creado, se habilita ahí la opción "Asociar proyectos". Si no ve ninguna opción en su proyecto, es porque ningún cuadro de mando tiene esa asociación habilitada para él.
No lo habilite sin coordinar con el área de Planeación. Asociar proyectos sin alineación hace que le aparezcan proyectos no vinculados dentro de la estructura ya construida por esa área, entorpeciendo su planeación estratégica.

Con la asociación correctamente habilitada, el proyecto aparece reflejado en el tablero de mando, permitiendo ver cómo su ejecución física aporta a las metas estratégicas de la entidad.
